# 节点格式与变长记录寻址

状态：已有正文 · 代码：[layout.go](../../btree/layout.go)

## 问题

一个 B+Tree 节点用一张 4096 字节的页表示，页内存放有序的变长 KV。记录长度各不相同，不能用"下标 × 固定记录长度"定位，所以用一个定长的 offset 数组记录每条记录的边界，从而支持按下标定位和页内二分。

编码与解析必须一致；格式一旦改变，所有读写这张页的代码都要一起改。

## 布局取舍：每页开销与每条开销

```text
扇出 ≈ 页内可用空间 / 每个目录项平均占用
扇出越大 → 树越矮（log_B n）→ 沿路径访问的页越少
```

页头是每页一次的开销，offset、klen、vlen 是每条记录重复的开销。每页固定开销被很多条记录摊薄（例如 4 字节摊到 180 条记录，每条约 0.02 字节），而每条记录的开销直接乘以记录数，所以设计时优先压缩每条记录的开销。当前完整页头是 12 字节。

## 整体结构

```text
byte 0
┌────────────────────────────────────────────────┐
│ HEADER  (固定 12 字节, 每页一次)               │
│   type    uint16   叶子=1 / 内部=2             │
│   nkeys   uint16   本节点记录数                │
│   sibling uint64   右兄弟页号（0=无）          │
├────────────────────────────────────────────────┤
│ OFFSET 数组  (nkeys × 2 字节, 每条一项)        │
│   offset[i] uint16  第 i 条记录的【终点】      │
│   (相对 KV 区起点; 定长 → 可二分)              │
├────────────────────────────────────────────────┤  ← KV 区起点 = 12 + nkeys*2
│ KV 区  (变长, 从前往后堆)                      │
│   每条:  klen uint16 | vlen uint16 | key | val │
├────────────────────────────────────────────────┤
│ FREE SPACE                                     │
└────────────────────────────────────────────────┘
byte 4096
```

叶子和内部节点共用页头，内部节点也占着 8 字节 sibling 但填 0，换来共用的字段解析与记录定位。本项目的 CoW 树不维护叶子链（见 [扫描与叶子链接](../04-btree-tree/05-scan-and-leaf-links.md)），叶子的 sibling 目前也恒为 0。新页由 `make` 创建时空闲区为零，但解析不依赖"剩余空间全为零"。

## offset 数组：存结束位置

`offset[i]` 是第 i 条记录相对 KV 区起点的结束位置（不含终点）。公式中约定 `offset[-1] = 0`，代码不会真的读负下标。

```text
第 i 条相对起点   = offset[i-1]          （i = 0 时为 0）
第 i 条长度       = offset[i] - 相对起点
KV 区整页起点     = 12 + nkeys*2
第 i 条整页起点   = KV 区整页起点 + 相对起点
非空页已用字节    = 12 + nkeys*2 + offset[nkeys-1]
空页已用字节      = 12
剩余空间          = 4096 - 已用字节
```

一个数组同时给出记录边界、记录长度和 KV 区已用大小。查找时，记录 `mid` 的起点来自前一项的结束偏移，再加上 KV 区起点。公式依赖合法页：记录连续有序、偏移正确且不越界；这些 helper 不做完整的损坏页校验。

## 记录编码

```text
┌────────┬────────┬───────────┬───────────┐
│ klen   │ vlen   │ key bytes │ val bytes │
│ uint16 │ uint16 │ (klen)    │ (vlen)    │
└────────┴────────┴───────────┴───────────┘
```

- 叶子：value 是用户数据。
- 内部页：value 是 8 字节孩子页号（`vlen = 8`），key 是孩子子树的实际最小 key，见 [内部节点布局与路由](10-internal-layout-and-routing.md)。
- key 按升序存放，这是页内二分的前提。

记录整页起点为 `start` 时：

```text
key   = [start+4, start+4+klen)
value = [start+4+klen, start+4+klen+vlen)
```

offset 划分记录与记录，长度字段划分记录内部的 key 与 value。只知道记录总长时，无法判断 `abc` 是 `a→bc` 还是 `ab→c`。

## 常量与字段宽度

```go
const (
    PageSize = 4096

    NodeLeaf     = 1
    NodeInternal = 2

    offType    = 0  // uint16
    offNKeys   = 2  // uint16
    offSibling = 4  // uint64
    headerSize = 12 // = 2 + 2 + 8
)
```

| 字段 | 宽度 | 频率 | 理由 |
| --- | --- | --- | --- |
| type | uint16 | 每页 | 字段对齐，留出类型编号空间 |
| nkeys | uint16 | 每页 | 一页能放的记录数远小于 65535 |
| sibling | uint64 | 每页 | 与页号类型一致 |
| offset[i] | uint16 | 每条 | 页内偏移不超过 4096 |
| klen / vlen | uint16 | 每条 | 页内记录长度受页容量限制 |

一页能放多少条由实际字节决定，不存在对所有 key/value 长度通用的固定上限；容量计算见 [叶子容量与错误](06-leaf-capacity-and-errors.md)。页号 0 表示"没有页"（设计中页 0 留给 meta），所以 `sibling = 0` 可以表示没有右兄弟。页号是逻辑编号，固定 8 字节，不是内存地址。

## 完整 hex 例子：cat→meow、dog→woof、sibling=7

```text
       00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F
0x00 │ 01 00 02 00 07 00 00 00 00 00 00 00 0B 00 16 00 │ ................
0x10 │ 03 00 04 00 63 61 74 6D 65 6F 77 03 00 04 00 64 │ ....catmeow....d
0x20 │ 6F 67 77 6F 6F 66 00 00 ...(free, 全 0)          │ ogwoof..........
       └─┬─┘ └─┬─┘ └──────┬──────┘ └─┬─┘ └─┬─┘
        type nkeys     sibling=7     off0  off1
        =1   =2       (uint64 LE)    =11   =22
```

- `01 00`：type = 1，叶子，小端。
- `02 00`：nkeys = 2。
- `07 00 00 00 00 00 00 00`：sibling = 7。
- `0B 00` = 11、`16 00` = 22：两条记录的结束偏移，第二条长 22 − 11 = 11 字节。
- KV 区从 byte 16 开始：`03 00` klen = 3，`04 00` vlen = 4，`63 61 74` 是 `cat`，`6D 65 6F 77` 是 `meow`。
- 已用 12 + 2×2 + 22 = 38 字节。

观察字节的方法见 [hexdump](../01-file-persistence/06-hexdump-and-file-inspection.md)。

## 相对偏移与整页位置：三条记录

`offset = [8, 21, 40]`，KV 区从整页偏移 18 开始：

| 日常称呼 | 代码下标 | KV 区内范围 | 长度 | 整页起点 |
| --- | --- | --- | --- | --- |
| 第一条 | 0 | [0, 8) | 8 | 18 |
| 第二条 | 1 | [8, 21) | 13 | 26 |
| 第三条 | 2 | [21, 40) | 19 | 39 |

若第三条 `klen = 3`、`vlen = 12`，则 key 范围是 `[43, 46)`，value 范围是 `[46, 58)`。

## 易混点

- **日常序号与代码下标**："第二条记录"是下标 1，不是下标 2。
- **相对偏移与整页地址**：相对偏移 21 不能直接当 `page[21]`；下标 2 的记录起点是 `page[39]`。
- **18 字节不是页头**：它是 12 字节页头加 3 × 2 字节 offset 表。
- **二分的中点是记录下标**，不是页面字节的中点。key 有序让比较后能排除半边记录；定长 offset 表让取得任意下标的起点不必扫描之前的记录。
- **没有 offset 表会怎样**：仍能顺序解析，但定位下标 i 需要依次读取此前每条记录的长度字段（不必读 value 内容），成本随 i 增长。每条 2 字节的 offset 项换来了常数时间的定位。

## 源码入口

[layout.go](../../btree/layout.go)：`kvAreaStart` 计算 KV 区整页起点，`kvStart` / `kvEnd` 计算相对边界，`getKey` / `getValue` 解码记录，`nodeUsedBytes` 汇总已用容量。其他页内布局方案见 [页内布局对照](../06-storage-comparisons/01-page-layout-alternatives.md)。

## 一页速记

1. 节点 = 4096 字节页；变长 KV 配定长 offset 数组。
2. 页头 12 字节：type(2)、nkeys(2)、sibling(8)。
3. offset 存结束位置，配合前一项得到起点、长度和已用容量。
4. 每条记录是 klen(2)、vlen(2)、key、value；内部页 value 为 8 字节孩子页号。
5. 每页开销被摊薄，每条开销乘以记录数；精确容量由实际字节决定。
