# 内部目录按字节分组与 key 长度上限

状态：已有正文 · 代码：[internal_split.go](../../btree/internal_split.go) 的 `maxKeySize`、`ErrKeyTooLarge`、`internalBuildSplit`

## 整棵树里要解决的问题

孩子更新后可能用多项目录替换一个旧项，父目录因此超过 4096 字节。内部节点分裂要把合并后的目录项按连续 key 范围分组，构建多张新内部页，再向更高父层交回各新页的最小 key 与页号。

示意（省略真正超页所需的更多目录项，页号仅示意）：

```text
原内部页 20：ant→10 | dog→25 | pig→31
孩子 25 更新后：dog→40 | eel→41
合并目录：ant→10 | dog→40 | eel→41 | pig→31

分组并分配新页号：
  内部页 60：ant→10 | dog→40
  内部页 61：eel→41 | pig→31

更高父层：用 ant→60 | eel→61 替换原 ant→20
```

内部页分裂只重新编码目录项，保留其中的孩子页号，不复制孩子内容。新内部页仍在同一层，下面孩子的深度不变。若更高父层也超页，继续向上传递；根分裂见 [根分裂与发布](../04-btree-tree/04-root-split-and-publication.md)。

## 不变量与易混点

- 每个孩子对应一条"实际最小 key → 孩子页号"，分组后每条目录项恰好保留一次，顺序不变。
- 页 61 中的 `eel→41` 必须保留：更高父层的 `eel→61` 用来找到页 61，页 61 里的 `eel→41` 用来找到孩子 41。不能把后者当作"提升 key"搬走，这与教材中"分隔 key 上移"的写法不同。
- 临时记录 `internalEntry{minKey, childPageID}` 与 offset 不同：offset 是编码进某张具体页之后的定位信息。确定分组后每张新页都要重新生成 offset。

## 为什么要限制 key 长度

每个目录项占 offset(2) + 长度字段(4) + 完整 key + 页号(8) = 14 + len(key) 字节，页头另算 12 字节。

两个不同的 3000 字节 key 各自能和短 value 放进独立的叶子，但父目录保存它们需要 12 + 2 × (14 + 3000) = 6040 字节。若把父目录拆成两个单孩子页，更高一层仍然要保存这两个长 key，永远无法汇合成一个根。

这是"固定大小的节点页 + 保存完整最小 key + 没有溢出存储"这组设计带来的约束，不是所有数据库都只能限制 key 长度（其他方案见 [长 key 与分隔键](../06-storage-comparisons/02-large-keys-and-separators.md)）。

本实现选定 **1000 字节**上限：每项最多 1014 字节，任意四项加页头最多 12 + 4 × 1014 = 4068 字节，一页一定装得下。上限在 `internalBuildSplit` 中检查，整树 `put` 入口也检查所有用户 key：任何 key 都可能在以后的分裂中成为某棵子树的最小 key，不能等它进入父目录时才拒绝。value 不进入父目录，只受叶子记录容量约束。

## 分组规则

先合并出有序的完整 entries，再按实际编码字节从左到右装组：下一项放不下就结束当前组。分组连续、非空、各自不超页，不先构造超容量的页。例：每项 1000 字节，六项分成四项与两项，分别占 4012 与 2012 字节。这个方案偏向先填满左页，不保证各页均衡。

**尾组只有一项时，把前一组的末项挪过来。** 在 1000 字节上限下任意四项都装得下，所以因装满而结束的前一组至少有四项，挪走一项后仍有至少三项，末组两项也必然装得下。

用 `groupEnds` 保存每组的右开结束下标（不是项数）。例：`[4, 8, 9]` 表示 ABCD / EFGH / I，末组项数 9 − 8 = 1；把前一个分界 8 减为 7，得到 `[4, 7, 9]`，即 ABCD / EFG / HI。输入记录不移动，只改变构建页时使用的切片区间。`lastGroupIndex > 0` 保证确实存在前一组。

末组不是单项时不调整，例如倒数第二页 85 项、最后一页 13 项：规则只消除单孩子页，不追求页间均衡，而且记录长度不同，项数也不代表字节占用。

**为什么消除单孩子内部页。** 单孩子页仍能正确路由，但没有分支作用，只多一层访问和一张页；任其反复产生会形成单孩子链。也不能把某个局部单孩子页直接绕过，那会缩短这条路径，破坏"所有叶子同深度"。在同层分组之间调整目录项（ABCD / E 改为 ABC / DE）既保留深度，又让两页都有分支。这是多页分组结果的最低孩子数约束，不代表单项目录无法编码，也不是完整的最低占用或删除再平衡策略。

## internalBuildSplit 的步骤

1. 检查整组目录：非空、key 严格递增、页号非零，否则返回 `nil, ErrInvalidInternalEntries`；key 超过 1000 字节返回 `nil, ErrKeyTooLarge`。多类错误同时存在时不承诺优先级。
2. 按字节装组，记录 `groupEnds`。每项占 14 + len(key)，新页从页头的 12 字节开始累计。
3. 尾组只有一项时，前一个分界减一。
4. 对每个区间调用 `internalBuild`。结果页 sibling 全为 0，各自独立拥有字节；任何编码错误都返回 nil，不交出部分结果。

**完整检查必须放在分组之前。** 若输入按容量分为 `[ant, cat]` 与 `[bee, dog]`，每组内部都递增，但跨组的 cat/bee 已经逆序；只让 `internalBuild` 分别检查每组会漏掉这个错误。

函数支持一般的非空目录，结果不限于两页或三页；单项输入返回单页。`groupEnds` 临时空间 O(p)（p 为结果页数），分组扫描 O(n)，另计 key 比较、复制和页分配。孩子真实存在、minKey 与子树一致、子树范围合法仍由调用者保证。

## 测试

[internal_split_test.go](../../btree/internal_split_test.go)：构建用例覆盖空 key 与二进制 key、1000 字节上限、恰好 4096 与超出一字节、两页与三页分组、尾项调整、多条短 key；逐条核对完整 key 与 uint64 页号、跨页顺序、容量、sibling、输入不变和结果独立。测试中临时建立上一层目录，用独立的线性规则验证精确命中、间隙和首尾查询。错误用例覆盖空目录、零页号、重复与逆序（含跨组交界）、1001 字节和超过 uint16 长度的 key，以及已形成两页之后才出现的错误，均确认不返回部分结果、输入不变。
