# 文件页、页号与元信息入口

状态：已有正文 · 代码：[pager.go](../../pager/pager.go) 的 `PageSize`、`ReadPage`、`Open`；[db.go](../../btree/db.go) 的 `metaSlotFor`

## 问题：每次修改都重写整个文件吗

整文件替换（临时文件 + rename）在文件小的时候很好用，但修改 1 字节也要重写 1 GB 时，成本随文件大小增长。分页的起点是把文件划成固定大小的片段，只定位和处理需要的页。分页本身还没有解决事务提交与恢复。

## 文件是一串字节

文件内容是从 offset 0 到 N − 1 的字节序列。行、列、页和表都是上层格式的解释，不是字节流天然带有的分组：按字符编码解读得到字符，按 `int32` 解读得到整数，按数据库页布局解读得到节点与 key/value。这套解读规则就是**文件格式**。

文件可以随机访问，例如 `lseek(fd, offset, ...)` 后在指定位置读写，定位一页不需要从头扫描。

## 逻辑页与页号

本项目 `PageSize = 4096`，约定每 4096 字节为一页，边界靠固定长度计算，不依赖分隔符。

```text
page N 的字节范围 = [N × 4096, (N + 1) × 4096)
读 page N         = 定位到 N × 4096，再读 4096 字节
```

页号到文件偏移是 O(1) 的算术定位，这不等于根据用户 key 找到页——后者由树的路由完成。

4096 是本项目的格式约定。常见说法是"SSD 写入粒度、OS 页、文件系统块都是 4 KiB，所以 4 KiB 最优"，但这些值因平台和设备而异，OS 页大小应在运行平台上查询；Linux `mmap` 的 offset 对齐以系统页大小为准。（[mmap(2)](https://man7.org/linux/man-pages/man2/mmap.2.html)）

## 一页里放什么

页内布局由格式设计决定，最简单的形状是"页头 + 数据"：

```text
byte 0    byte 2    byte 4                         byte 4096
  ├─────────┼─────────┼─────────────────────────────────┤
  │ 类型    │ 记录数  │ key/value 内容……                │
  └─────────┴─────────┴─────────────────────────────────┘
```

当前叶子页的精确布局还有 sibling、offset 表与记录长度字段，见 [节点格式](../03-btree-pages/03-node-format-and-record-addressing.md)。

## 元信息从哪里开始找

打开数据库时需要一个稳定入口找到根和其他元信息，这就是固定位置的 meta 页（页 0 与页 1 两个槽位，[db.go](../../btree/db.go) 的 `metaSlotFor`），见 [文件格式与元数据校验](../05-storage-recovery/03-file-format-and-meta-validation.md)。

## 不变量

- 同一文件格式内页大小固定，页号到偏移的计算必须一致。
- "页已分配""文件足够长""本进程能通过映射访问"要分开判断，见 [Pager 的三个范围](05-chunked-mmap-and-pager-ranges.md)。
