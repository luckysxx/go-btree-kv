# 整文件保存：临时文件与原子替换

状态：部分已整理 · 代码：[atomic-save/main.go](../../experiments/atomic-save/main.go) 的 `SaveData1/2/3`、`writeLoop`

## 先写临时文件，再替换路径

```text
写 path.tmp.<随机后缀> → fsync → rename(path.tmp.<后缀>, path)
```

先准备完整内容，再用同文件系统内的 rename 替换目标路径。临时文件使用随机后缀，并以 `O_CREATE | O_EXCL` 创建，避免文件名碰撞时覆盖别人已经创建的临时文件。

这一步保证的是替换时的**版本可见性**：观察者通过路径看到完整的旧版本或完整的新版本。它不能协调多个进程"读 → 改 → 写回"的业务更新，丢失更新的例子见 [原子性与并发控制](03-atomicity-and-concurrency.md#场景-2lost-update更新丢失)。

## 文件内容与文件名要分别同步

文件数据的同步和路径替换所涉及的**父目录**同步需要分别考虑。`SaveData3` 调用了文件 `Sync`，但没有同步父目录，所以它还不是完整的持久化保存。函数名、注释或一次正常运行都不能证明断电安全。平台与设备缓存的限制、同步失败时的承诺边界见 [写入与同步](04-write-sync-and-errors.md)。

## 实验说明

`atomic-save` 实验比较完整保存循环的耗时，包括打开、写入、可选的文件同步和 rename，不是单个 fd 上的纯 write 基准。实验在独立临时目录中运行，参数与运行方式见 [实验入口](../../experiments/README.md)。
