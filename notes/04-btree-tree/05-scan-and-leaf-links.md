# 扫描与叶子链接

状态：已有正文 · 代码：[cursor.go](../../btree/cursor.go)

## 要解决的问题

按 key 从小到大读出一段范围内的记录，例如 `[k0100, k0200)`，或者整棵树。难点在跨叶子：读完一张叶子后，怎样找到按 key 顺序紧挨在右边的那张。

## 叶子兄弟链与 CoW 不相容

页头有 sibling 字段（页头 4～12 字节，`nodeSibling` 读取），教材里带叶子链表的 B+Tree 就用它直接跳到右兄弟。sibling 保存的是按 key 顺序的右兄弟页号；页号只表示位置，key 顺序与页号顺序可以不同。

在 CoW 树中维护它代价极高。叶子 A → B → C → D，更新 C 得到 C'：

1. B 的 sibling 仍指向旧 C，CoW 不许原地改 B，只能复制出 B' 指向 C'；
2. A 又指向旧 B，再复制 A'……

C 左侧每一张叶子及其父页都要重建，写放大从"树高"变成接近整棵树。所以 bbolt、LMDB 等 CoW B+Tree 不维护叶子链；带链表的是原地更新的 B+Tree，例如 InnoDB 的叶子双向链表。

本实现保留页格式中的 sibling 字段，但恒为 0（全树检查会验证这一点），扫描改用游标。

## 游标：保存从根到叶子的路径

游标下降时每层记一个 `cursorFrame{pageID, page, index}`，整条路径存成一个栈：

- 内部页的 `index`：当前走的是第几个孩子。
- 叶子的 `index`：当前读的是第几条记录；等于 nkeys 表示这张叶子读完了。

`page` 是顺手缓存，回到这一层时不必再取；`pageID` 用于发现环。**位置信息（index）是关键。**

为什么需要显式的栈：递归的 `getFrom` 由 Go 调用栈记住路径；游标要在两次 `next` 之间把控制权交还调用者，调用栈不复存在，只能把每层的"帧"存进切片。这相当于把递归 DFS 改写成显式栈的迭代 DFS，以便随时暂停和恢复。

切片当栈用时，**末尾是栈顶**：`stack[0]` 是根，`stack[len-1]` 是当前叶子；压栈 `append`，弹栈 `s[:len(s)-1]`，都在末尾，不需要挪动元素。

## 一次完整遍历

```
                    根 R
             [ a1→L  |  c1→Rt ]
          左 L                   右 Rt
   [ a1→叶1 | b1→叶2 ]     [ c1→叶3 | d1→叶4 ]
 叶1{a1,a2}   叶2{b1,b2}   叶3{c1,c2}   叶4{d1,d2}
```

栈写成 `页:index`，从栈底到栈顶：

| 调用 | 过程 | 之后的栈 | 读到 |
| --- | --- | --- | --- |
| first | 从 R 一路走第 0 个孩子 | `R:0 L:0 叶1:0` | a1 |
| next | 叶1 的 index +1 | `R:0 L:0 叶1:1` | a2 |
| next | 叶1 读完 → 弹出，L 的 index +1 → 走到叶2 | `R:0 L:1 叶2:0` | b1 |
| next | | `R:0 L:1 叶2:1` | b2 |
| next | 叶2 读完 → 弹出；L 的 index +1 = 2，L 也走完 → 弹出；R 的 index +1 → 从 Rt 一路走第 0 个孩子 | `R:1 Rt:0 叶3:0` | c1 |
| next | | `R:1 Rt:0 叶3:1` | c2 |
| next | 叶3 读完 → 回到 Rt，换到叶4 | `R:1 Rt:1 叶4:0` | d1 |
| next | | `R:1 Rt:1 叶4:1` | d2 |
| next | 叶4、Rt、R 依次走完，栈弹空 | 空 | 结束 |

"换到下一张叶子"就是：往上找到第一层"还有下一个孩子"的页，换到那个孩子，再一路往左下走到叶子；找到栈空都没有，就说明全部读完。

## 接口

```go
c := tr.newCursor()      // 拿住树当前的根
c.first() / c.seek(k)    // 定位到最小记录 / 第一条 ≥ k 的记录
for c.valid() {          // 还停在一条记录上吗
	c.key(); c.value()   // 读当前记录（借用页内字节）
	c.next()             // 前进一条
}
```

范围约定左闭右开 `[start, end)`：`seek(start)` 定位，读到 `key ≥ end` 时由调用者停止。

各函数的分工：

- `first`：从根一路走第 0 个孩子（`descendLeftmost`）。
- `seek`：内部页按 `internalChildIndex` 选孩子，叶子用 `leafSeek` 定位。
- `next`：叶子 index +1。
- `valid`：只回答"现在能不能读到一条用户记录"，不移动游标。用户记录只存在叶子里，所以要求栈顶是叶子且未读完；栈顶是内部页只会出现在换叶子的过程中。
- `key` / `value`：读栈顶叶子的当前项，要求 `valid()` 为真。
- `cursorFrame.exhausted()`：这一层的项是否用完（叶子是记录读完，内部页是孩子走完），`valid` 与换叶子共用这一个判断。

接口风格的另外两种写法：`Next` 返回 bool（`bufio.Scanner`、`sql.Rows`），或 `Next` 直接返回 key/value、以 nil 表示结束（bbolt Cursor）。单独的 `valid`（同 RocksDB/LevelDB Iterator）让 first/seek/next 共用一个判断，调用者也能随时查询。

## 不停在"叶尾之后"

游标停在某张叶子的 `index == nkeys` 时，处在一个尴尬的状态：这张叶子读完了，后面的叶子可能还有数据，但 `valid()` 只看栈顶，会返回 false，调用者的循环就提前结束了。三处会进入这个状态：

| 调用 | 原因 | 例（两层树 `L1{ant,cat} | L2{dog,fox}`） |
| --- | --- | --- |
| seek | target 大于这张叶子的所有 key，leafSeek 返回 nkeys | `seek("cow")` 停在 `L1:2` |
| next | index +1 后越过叶尾 | 读完 cat 后 |
| first | 最左叶子是空的 | 空树的根 |

所以 first、seek、next 返回前都经过同一个判断（`skipExhaustedLeaf`）：栈顶叶子读完了就换到下一张叶子，换叶出错则清空栈。保证返回后游标只有两种状态：停在一条真实记录上，或者无效（全部读完或出错）。把 `valid` 改成 `index <= nkeys` 解决不了问题：`key()` 会越界读，游标也不会走到下一张叶子。

换叶子（`nextLeaf`）的循环每轮先弹栈，这一个动作同时处理三种情况：弹掉读完的叶子、弹掉孩子已走完的一层、弹掉走到的空叶子。返回只有三个出口：停在一张非空叶子上（`valid()` 为真时返回）、栈弹空、出错。

## 快照、借用与边界

- **快照**：游标创建时拿住当时的根。扫描中途别人 put 并发布新根，游标仍在旧树上走，看到一致的旧版本。这是 CoW 的收益，维护叶子链的原地更新树没有这个性质。
- **借用**：key/value 借用页内字节，有效期与 get 相同（见 [根定位与整树查找](02-root-and-tree-search.md#value-借用还是复制)）。
- **边界**：空树与起点大于全部 key 时游标直接无效；起点落在两张叶子之间时自动走到下一张叶子的第一条记录；空叶子被跳过。

## 常见错误

- **用 `valid()` 判断内部页"还有没有下一个孩子"。** 弹出叶子后栈顶是内部页，`index < nkeys` 的含义变成"当前孩子存在"，永远为真，于是一路弹到栈空，每次只读完第一张叶子。应先把该层 index +1，再判断是否用完。
- **往下走时传入栈顶页自己的页号。** 它已经在栈里，会被当成环；起点应是它的第 index 个孩子。
- **走到叶子后不返回。** 下一轮会把新叶子弹掉。
- **持有指向切片元素的指针后再 append。** `top := &c.stack[i]` 之后调用会 append 的函数，底层数组可能换位置，`top` 指向旧数组；应先算好需要的值，之后不再用 `top`。
- **让同一个函数按页类型返回相反含义。** 例如让 `valid` 对叶子表示"有记录"、对内部页表示"已走完"：读代码的人要翻实现才知道意思，调用者的保护也只能靠别处保证栈顶是叶子。共同的判断应单独命名（`exhausted`）。
