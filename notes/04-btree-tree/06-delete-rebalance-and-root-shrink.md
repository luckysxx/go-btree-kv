# 删除、再平衡与根收缩

状态：部分已整理 · 代码：[tree.go](../../btree/tree.go) 的 `delete`、`remove`、`commitRoot`、`shrinkRoot`；[leaf.go](../../btree/leaf.go) 的 `leafDelete`；[internal.go](../../btree/internal.go) 的 `internalRemoveChild`

首版范围：删除记录、把删空的页从树上摘掉、根收缩。合并与借位（完整再平衡）未实现。

## 接口

```go
func (t *tree) delete(key []byte) (found bool, err error)
```

key 不存在时树**完全不变**：不新建页，也不发布新根（bbolt 对不存在的 key 同样直接返回 nil）。key 存在时与 put 一样路径复制，旧根仍是删除前的完整版本。超过 1000 字节的 key 不可能被写入过，直接返回未找到。

## 孩子交回的三种结果

删除后孩子可能：没变（key 不存在）、变成一张新页、整张页没了（叶子删空）。沿用 put 的"交回目录项"，再加一个 bool：

```go
func (t *tree) remove(pageID uint64, key []byte, visited []uint64) (entries []internalEntry, changed bool, err error)
```

| 结果 | 含义 | 父页怎么做 |
| --- | --- | --- |
| `changed == false` | 子树没变 | 本页也不复制，继续向上交回"没变" |
| `changed`，`entries` 非空 | 用 entries 替换这个孩子 | 同 insert：`internalReplaceChildSplit` + `savePages` |
| `changed`，`entries` 为空 | 这棵子树已空 | 本页删掉这个孩子的目录项（`internalRemoveChild`）；若它是本页唯一的孩子，本页也空了，继续向上交回"没了" |

"没了"可以一层层往上传。叶子删空时不能把空页交给 `savePages`：它会对 nkeys = 0 的页读 `getKey(page, 0)`，而且会在树里留下空叶子。

**删除也可能让父页变大。** 删掉某棵子树的最小 key 后，新的最小 key 可能更长（例如从 4 字节变成 1000 字节），父目录项随之变长，父页可能分裂，甚至根分裂。所以替换分支仍要用 `internalReplaceChildSplit`，`commitRoot` 也要能处理多项。

## minKey

删除子树最小 key 后，新页的第一个 key 成为新的 minKey，由 `savePages` 自动更新（删掉 dog 后，父目录中该项变为 fox）。若不更新，查找仍然正确（过时 minKey 小于实际最小值，落在两者之间的 key 本就不存在），但破坏"minKey 等于子树实际最小 key"这条不变量，与 [递归 Put](03-recursive-put-and-path-copy.md#minkey-随之更新) 中的情况相同。

## 空页与根收缩

两个 build 函数对空页的态度相反：`leafBuild(nil, 0)` 返回合法的空叶子（空树的根）；`internalBuild(nil)` 拒绝，没有孩子的内部页没有意义，读取时会被当作损坏。

`commitRoot` 处理根这一层交回的结果：

- **根是内部页，只剩一个孩子**：这一层不起路由作用，任何查找都必然走唯一的孩子，却让每次操作多走一层。`shrinkRoot` 让孩子直接当根，树高 −1；若孩子也是单孩子内部页则继续提升。这不是正确性问题，但不收缩的话，大量删除之后树高永远降不下来。
- **根是内部页，一个孩子都不剩**：内部页不能为空，此时整棵树已无数据，按"空树 = 空叶子根"新建一张空叶子作根。
- **根本身是叶子，删掉最后一条**：得到的空叶子根就是合法的空树，不能把它摘掉。根这一层永远存在。

## 为什么只在根收缩

深度从根算起，所有叶子都在根下面。根只有一个孩子时，全部叶子都在这个孩子的子树里，提升孩子会让**每一片**叶子的深度同时减 1，"所有叶子同深度"仍然成立。

中间页只管辖一部分叶子。跳过中间的单孩子页，只有经过它的路径变短，其余路径不变，叶子深度就不一致了：

```
        R                      若让 C 直接替代 B：
      /   \                    L3、L4 深度 2，L1、L2 深度 3
     A     B   ← 只有一个孩子
    / \    |
   L1 L2   C
          / \
         L3 L4
```

一般规律：**B+Tree 的高度只在根处变化**。长高靠根分裂，变矮靠根收缩；中间层不能增删层次，只能改变同一层的宽度。要消灭中间层的单孩子页或过稀的页，只能在同一层与兄弟页合并或借位。合并会让父页少一项，可能一路向上传，最后在根处表现为根收缩。

因此首版里中间层的单孩子内部页是合法的：路由正确，只是多占一页、查找多走一次读取。

注意区分"摘掉"和"跳过"。内部页的孩子**全部没了**时，从父页摘掉它，任何一层都可以：这条路径下已经没有叶子，不涉及深度。内部页**还剩一个孩子**时，把孩子提上来、跳过本页，会让下面的叶子变浅，只有根可以这样做。

## 不做合并的代价

只摘除空页、不做合并与借位时，大量删除后叶子可能只剩一两条记录：空间浪费，扫描要多读页，树高偏高。查找仍然正确，删空的页也会被摘除，不会无限堆积，首版可以接受。bbolt 在提交时把填充率低于阈值的节点与兄弟节点合并。

## 页号不回收

被删掉的页只是从新版本的树上摘掉，页存储中的页号不回收：旧根可能仍有读者（快照），回收时机要等读事务与空闲页管理（批次 4）。
