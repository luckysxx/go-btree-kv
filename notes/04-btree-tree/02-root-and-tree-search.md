# 根定位与整树查找

状态：已有正文 · 代码：[tree.go](../../btree/tree.go) 的 `tree`、`newTree`、`get`、`getFrom`

## 页、层级与根

目录页就是树的内部节点；内部页和叶子页同为 4096 字节的页，页号只表示位置，不代表层数。内部节点的孩子可以仍是内部节点，此时目录 key 必须是整棵孩子子树的最小 key。节点不保存父页号：向上需要时，靠查找时的递归栈或显式路径回到父层（见 [递归 Put](03-recursive-put-and-path-copy.md)）。

根页号是整棵树的入口。内存版本中它是树对象的一个字段；落盘后要写在固定位置（meta 页），打开数据库时先读 meta 得到根，再逐层下降。

## 树对象放什么

树是 KV API 之下的**索引层**：给定根页号和页存储，在页之间找 key。对外的 Open/Get/Put/Delete、事务、提交、读写者生命周期属于更上层（E 组）。对照 bbolt 的分层：`DB（对外）→ Tx（事务）→ Bucket（一棵树的根）→ Cursor / node`，这里的树对象大致相当于 Bucket。

```go
type tree struct {
	store *memPageStore
	root  uint64
}
```

按"结构体只放跨调用存活的状态"的标准（见 [内存页存储](01-memory-page-store.md#什么时候用结构体和方法)），树只需要页存储和根页号。两类常见的多余字段：

- **最近访问的 KV 缓存。** 放错了层：CoW 下旧根可能仍有读者，只按 key 的缓存分不清版本，Put 后还要失效；页都在内存时它几乎省不了什么；map 不记顺序，做不到"最近 N 个"。真实系统在页这一层缓存（自管 buffer pool，或 mmap 背后的内核页缓存；bbolt 自己不缓存）。缓存替换的实验安排在 B08。
- **访问路径 / 节点类型。** 节点类型随时可从页头读出；本次查找经过哪些页只属于这一次操作，应是局部变量。放进结构体会被下一次调用或并发读者弄乱。

## 空树：空叶子根

两种表示：

| | 根页号为 0 | 一开始就有一张空叶子作根（bbolt 做法） |
| --- | --- | --- |
| Get | 开头判断一次 | 无特例：leafGet 在 nkeys = 0 的页上直接返回未找到 |
| 首次 Put / 删空 | 各需一个特例 | 无特例 |
| 结构体零值 | 是合法空树 | 不是，必须经 `newTree` 创建（要保存一页，所以返回 error） |
| 排查 | 被误写成 0 的根会被当成空树，静默查不到 | 根为 0 是非法状态，读取时得到 ErrPageNotFound |
| 代价 | — | 空库也占一页；落盘后建库要写出这一页 |

本实现采用空叶子根，于是有不变量"**根始终是一张存在的页**"。空叶子只允许出现在根，全树检查写成"非根叶子不能为空"。

## 查找

```go
func (t *tree) get(key []byte) (value []byte, found bool, err error)
```

三种结果：找到 `(v, true, nil)`；key 不存在 `(nil, false, nil)`；树损坏或缺页 `(nil, false, err)`。只有 `found=false` 且 `err=nil` 才表示 key 不存在。

`getFrom(pageID, key, visited)` 递归下降，按页类型分三支：

- 叶子：`leafGet` 页内查找。
- 内部页：`nkeys == 0` 报损坏（`internalChild` 要求非空），否则 `internalChild` 选孩子，递归。
- 其他类型：报损坏。

用递归还是循环在 Get 中等价，树高只有几层，不必担心栈深；递归调用栈天然记住父层，Put 的路径复制正要用到。

**防环。** 损坏的页可能让孩子指回祖先，下降会无限循环。每次查询用局部的 `visited []uint64` 记录路径上的页号，重复出现即报 `ErrCorruptTree`。路径只有几层，切片线性查找比 map 便宜。bbolt 的读路径不做这种检查，信任页内容，另提供 `tx.Check()` 单独遍历全树；每次查询都检查是教学实现的取舍，好处是出错立刻暴露。

**错误要带位置。** 成环、空内部页、未知类型用 `fmt.Errorf("%w: page %d …", ErrCorruptTree, …)` 带上页号和原因，调用方仍可用 `errors.Is` 判断类别；缺页沿用页存储的 `ErrPageNotFound`。

## value 借用还是复制

`get` 返回的 value 借用页内字节，不复制。借用何时失效：

- 内存版本不会失效：页存储不覆盖、不回收，只要还有切片引用，GC 就不会释放底层数组。GC 替我们"等所有借用结束"，但只管内存是否释放。
- GC 管不到**改写**：将来回收页并把新内容写进同一块字节（复用缓冲区，或 mmap 中同一页被新数据覆盖），借用者会静默读到别的内容。mmap 扩容重新映射后，旧切片指向已解除映射的地址，访问直接段错误，Go 无法拦截。
- Rust 用借用检查在编译期保证借用期间页不被改或释放；Go 没有生命周期，只能在运行时约定。
- bbolt 在运行时"等借用结束"，粒度是事务：value 只在事务期间有效；释放的页按事务号挂起，更早的读事务结束后才复用；读事务持有 mmap 读锁，重新映射要等读者退出。

结论：现阶段借用完全安全；引入页回收（D06 之后）或 Pager mmap（E 组）时，要么按事务约定有效期，要么在对外 API 边界复制。

## 常见错误

- **用数字而不是常量判断页类型。** `NodeLeaf = 1`、`NodeInternal = 2`，写成 `nodeType(page) == 0` 会让内部页分支永远进不去。
- **"不是内部页就当叶子"。** 内部页与叶子共用记录格式（内部页的 value 是 8 字节孩子页号），类型判错时不会崩溃，只会悄悄返回错误数据：内部页被交给 leafGet，查到目录 key `ant`，返回的"value"是小端的孩子页号 `\x01\x00…`。未知类型必须报错。
