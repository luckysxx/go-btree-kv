# 笔记 01：Unix 文件 API 基础

> 写数据库前必须打通的底层知识。Go 的 `os.OpenFile` 等都是 Unix `open(2)` 系统调用的薄封装，
> 所有数据库 / Web server / Redis / Nginx 底层都是这一套。

---

## 1. 文件描述符 (File Descriptor, fd)

内核为每个进程维护一张"打开文件表"，fd 就是这张表的索引（一个小整数）。

```
进程 PID=1234 的 fd 表：
┌────┬─────────────────────────┐
│ fd │ 指向哪个打开的文件         │
├────┼─────────────────────────┤
│  0 │ stdin  (键盘)            │  ← 进程启动时自动有
│  1 │ stdout (屏幕)            │
│  2 │ stderr (屏幕)            │
│  3 │ /Users/luckys/db.data   │  ← open 一次分配一个
│  4 │ /tmp/db.data.tmp.918273 │
└────┴─────────────────────────┘
```

- `open()` 系统调用：检查权限 → 在表里分配空槽位 → **返回那个数字**。
- `read/write/close/fsync` 等都用这个 fd 操作。
- `close()` 回收槽位。
- Go 里 `*os.File` 内部封装了一个 fd，可用 `fp.Fd()` 拿到底层 fd。

---

## 2. `open()` 的 flag 参数

用**位或 `|`** 拼起来，每个 flag 占一个 bit：

| Flag       | 含义                                              |
| ---------- | ------------------------------------------------- |
| `O_RDONLY` | 只读                                              |
| `O_WRONLY` | 只写                                              |
| `O_RDWR`   | 读写                                              |
| `O_CREATE` | 文件不存在就创建                                  |
| `O_EXCL`   | 配合 `O_CREATE`：**如果文件已存在就报错**         |
| `O_TRUNC`  | 打开时把文件截断为 0 字节（清空）                 |
| `O_APPEND` | 每次写都追加到末尾                                |

**例子**：`os.O_WRONLY | os.O_CREATE | os.O_EXCL`
翻译：「我要写这个文件，不存在就创建，**已存在就报错给我**」。

`O_EXCL` 的意义：防止两个进程挑了同一个临时文件名互相覆盖。

---

## 3. 文件权限 `0644`

Unix 文件权限，八进制：

```
0644 = rw- r-- r--
       │   │   └── 其他人：只读
       │   └────── 同组用户：只读
       └────────── 文件所有者：读写
```

- 只有**创建新文件**时（`O_CREATE`）才用到。
- 打开已有文件时此值被忽略。

---

## 4. 数据流：write 之后数据在哪？

这是理解 `fsync` 为什么必要的关键：

```
你的程序
   │ write(fd, data)
   ▼
┌──────────────────────┐
│ 内核 Page Cache       │  ← write() 返回成功了，数据在这里
│ (内存中)              │
└──────────────────────┘
   │ fsync(fd)  ← 必须显式调用，否则什么时候落盘是内核说了算
   ▼
┌──────────────────────┐
│ 磁盘 (持久化存储)      │
└──────────────────────┘
```

- `write()` 返回成功 ≠ 数据在磁盘上。
- 系统断电时，page cache 里的数据全丢。
- `fsync(fd)` 强制内核把这个文件的脏页刷到磁盘。
- 想保证目录项变更（如 rename）也落盘：要对**父目录**也 fsync。

---

## 5. 常用系统调用一览

| 系统调用   | 作用                                       | Go 对应                  |
| ---------- | ------------------------------------------ | ------------------------ |
| `open()`   | 打开/创建文件，返回 fd                     | `os.OpenFile`            |
| `read()`   | 从 fd 读字节                               | `fp.Read`                |
| `write()`  | 向 fd 写字节                               | `fp.Write`               |
| `close()`  | 关闭 fd                                    | `fp.Close`               |
| `fsync()`  | 强制把文件的脏页刷到磁盘                   | `fp.Sync()`              |
| `rename()` | 原子地重命名文件（同文件系统内）           | `os.Rename`              |
| `unlink()` | 删除文件                                   | `os.Remove`              |
| `lseek()`  | 移动 fd 的读写位置                         | `fp.Seek`                |
| `mmap()`   | 把文件映射到进程地址空间                   | `syscall.Mmap` / 第三方  |
| `flock()`  | 文件锁                                     | `syscall.Flock`          |
