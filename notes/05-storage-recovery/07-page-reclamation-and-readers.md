# 页回收与读者

状态：部分已整理 · 代码：[db.go](../../btree/db.go) 的 `releasePending`、`rebuildFree`；[tx.go](../../btree/tx.go) 的 `txPageStore.save`、`replace`、`free`；[tree.go](../../btree/tree.go) 中调用 `store.free` 的位置

## 问题

CoW 每次修改都产出新页，旧页在新版本里不再被引用。只分配不回收，文件只会一直变大：即使数据库里只有几条记录，反复修改也会让文件无限增长。过早回收，又会破坏仍在使用旧页的读者与崩溃恢复。

## 两类可回收的页

| | 事务内的过时页 | 旧版本的页 |
| --- | --- | --- |
| 来源 | 事务自己新建、又被自己从树上摘掉的页（例如删空的叶子） | 提交时被替换下来的已提交页 |
| 谁见过它 | 只有这个事务 | 读事务可能正在看；崩溃后可能要退回到它 |
| 何时可重用 | 立即，在同一事务内 | 满足下面两个条件之后 |

## 旧版本的页何时可重用

设事务 T 释放了页 P（P 属于版本 T−1 或更早）：

- **恢复**：T 自己不能重用 P。T 提交到一半崩溃时要退回版本 T−1，P 必须完好；T 成功提交后，退路是版本 T，它不引用 P。因此最早由事务 T+1 重用——T 不知道自己能否成功，T+1 开始时 T 已经成功。
- **读者**：版本号小于 T 的读事务可能还在看 P；版本号不小于 T 的读事务看到的版本里没有 P。因此要等所有版本号小于 T 的读事务结束。

合起来：**事务 T 释放的页，在 T 提交之后、且没有版本号小于 T 的读事务时，可以重用。**

## 记录方式

只需要三样状态：

- **空闲清单**：可以马上重用的页号。
- **待回收表**：按释放它的事务号分组，`pending[T]` 是事务 T 释放的页。
- **读者登记表**：每个读事务开始时登记它所读的版本号，结束时注销；只关心其中最小的一个。

判断只有一条：`pending[T]` 在 T 不大于最小读者版本号时移入空闲清单；没有读者时全部移入。不需要为每个读事务维护状态，也不需要单独跟踪"某个根是否已被释放"——页按释放它的事务号挂起，这一信息已在其中。

```
写事务开始：把满足条件的 pending 移入空闲清单；复制一份空闲清单给事务
分配页号：  副本中有空闲页就用，否则推进高水位
释放页：    本事务新建的页 → 放回副本（立即可重用）
            已提交的页     → 记入本事务的释放列表
提交成功：  用副本替换空闲清单；pending[本事务号] = 释放列表
回滚：      丢弃副本与释放列表，什么都不用恢复
```

空闲清单与高水位一样按"事务开始时复制、提交成功才发布"处理，回滚因此不需要任何撤销。

长时间不结束的读事务会拖住回收：它之后释放的页都留在待回收表中，文件持续增长。

## 空闲清单是否持久化

重启后可以只凭 meta 重新算出：

```
空闲页 = [第一张数据页, 高水位) 中的全部页 − 从根可达的页
```

重启时没有任何读事务，算出的空闲页立即全部可用，待回收表为空。可达页只需读内部页即可得到（叶子的页号在父页中）。

| | 持久化（bbolt 默认） | 重启时重算（bbolt 的 `NoFreelistSync`） |
| --- | --- | --- |
| 打开 | 直接读出 | 读一遍全部内部页 |
| 每次提交 | 多写空闲清单所占的页 | 不多写 |
| 复杂度 | 清单本身占用页，这些页的分配与释放又会改变清单 | 文件格式不变 |

本项目采用重启时重算。

**退路只保证一版。** 重算只看被选中的那份 meta，另一个槽位中上一版用到的页会被算作空闲并重用；之后若再退回上一版，它的页可能已被覆盖。bbolt 同样如此。

## 账目检查

任意时刻：可达页、空闲页、待回收页两两不重叠，合起来恰好是高水位以下的全部数据页。重叠意味着一张在用的页会被重新分配（损坏）；有遗漏意味着页泄漏（空间浪费）。bbolt 的 `tx.Check` 中"reachable freed""unreachable unfreed""already freed"三项即对应这一检查。

## 工业对照：bbolt

freelist（[internal/freelist/shared.go](https://github.com/etcd-io/bbolt/blob/v1.5.0/internal/freelist/shared.go)）含 `pending map[Txid]…` 与 `readonlyTXIDs`。`beginTx` 登记读事务号，写事务开始时 `ReleasePendingPages` 取最小的读事务号，把更早事务的 pending 页移入可用列表（它只放出事务号严格小于最小读者的，比上面的规则保守一格）。`Rollback` 把回滚事务的 pending 页与分配记录撤销。freelist 默认作为页写入文件，其页号记在 meta 中；`NoFreelistSync` 时不写，打开时由 `db.freepages` 扫描全库重建。

## LSM 中的对应

LSM 回收的是旧 SST 文件，规则相同（概念见 [B+Tree 与 LSM](../06-storage-comparisons/03-btree-and-lsm.md)）：

- compaction 的新文件写好、MANIFEST 记录落盘后，旧文件不再属于当前版本——对应"事务 T 提交之后"。
- 读者可能仍持有旧的 Version（某一时刻的 SST 集合）。Version 带引用计数，归零后它独有的文件才能删除——对应"等读者结束"。
- 重启时，目录中不在 MANIFEST 当前版本里的文件是孤儿，直接删除——对应"重启时重算，立即全部可用"。

粒度不同：这里按页、按事务号分组；LSM 按文件、按 Version 引用计数。长读者拖住回收的问题两边都有。

## 大纲

- 文件收缩：高水位只增不减，空闲页只在文件内部重用；把尾部空闲页还给文件系统（未展开）。
