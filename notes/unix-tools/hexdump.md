# hexdump — 十六进制查看文件

## 做什么

把任意文件**逐字节**以十六进制 + ASCII 并排显示。
- `cat` 只能看文本文件（遇二进制字节会乱码或吞掉）
- `hexdump` 不解释字节，**直接展示原始内容**

→ 调试数据库 page 布局、二进制协议、文件格式时的核心工具。

---

## 怎么用

```bash
hexdump -C <文件>           # 最常用：Canonical 两栏格式
hexdump -C <文件> | head    # 只看前几行
hexdump -C <文件> | less    # 大文件分页看

# 只看文件特定字节范围
hexdump -C -s <offset> -n <length> <文件>
# 例：看 offset 4096 开始的 256 字节（第 1 个 page 的前 256 字节）
hexdump -C -s 4096 -n 256 db.dat
```

> 💡 **永远加 `-C`**。不加默认格式更紧凑也更难读。

替代品：
- `xxd <文件>` — 输出格式差不多，看个人喜好
- `od -A x -t x1z -v <文件>` — POSIX 标准，但参数难记

## 看输出

```
00000000  58 45 4c 4c 4f 20 78 4d  41 50 21 20 54 68 69 73  |XELLO xMAP! This|
└──┬───┘  └─────────────┬──────────────┘  └──────┬────────┘
偏移量    每个字节的十六进制值                    ASCII 解读
(offset)  16 字节一行，中间空格分隔               不可打印字节显示为 .
```

逐列拆解：
- `00000000` — 这一行从文件 offset 0 开始（十六进制）
- `58` — 第 0 字节，0x58 = 88 = ASCII `'X'`
- `45` — 第 1 字节 = `'E'`
- ...
- 右边 `|XELLO xMAP! This|` — 同样 16 字节按 ASCII 显示

**重复行的折叠**：连续相同的行会显示成一行 `*`，避免刷屏。
```
00000020   ... 65 2e 0a 00 00 00 ...
*
00001000  ...
```
`*` 表示中间一大段都是相同内容（通常是 `00 00 ...`）。

---

## 数据库开发中怎么用

写存储引擎时，每设计一个新的 page 布局（例如：
前 2 字节 = 类型，接下来 2 字节 = 记录数，后面 = key/value），
**用 hexdump 逐字节验证代码确实按这个布局写了**。

比 `fmt.Println` 有用 100 倍：
- println 看不到字节级的细节
- hexdump 直接看到磁盘上真实的字节

后面写 B+Tree 时每加一个功能（插入、分裂、删除），都会 hexdump 验证。
